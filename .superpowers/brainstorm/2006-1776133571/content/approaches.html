實作方式比較

三種技術路線，選一個最符合你需求的

A

純 SCSS 改造

只新增 / 修改 _ProjectListContent.scss 和 _TeamProject.scss，Vue 元件結構完全不動。速度最快，但受限於現有 HTML 結構，部分 Wise 卡片佈局無法完美還原（例如協作者頭像移到 footer 左側）。

優點

  • 風險最低，不影響任何邏輯
  • 改動範圍最小，易回滾

缺點

  • HTML 結構限制，無法完全重排版
  • Wise 卡片 footer 佈局較難對齊
B

SCSS + 局部 template 調整 ✦ 推薦

調整 ProjectListContent.vue 的卡片 template 結構（重排版面層次、調整 class 名稱），搭配完整 SCSS 重設計。不動任何邏輯、不動 props/emits，只改 HTML 標記和樣式。可以完整呈現 Wise 設計語言。

優點

  • 版面可以完全重排
  • 邏輯零改動，風險可控
  • 能完整還原 Wise 卡片設計

缺點

  • 需要小心不破壞 hover/showMoreOption 的 JS 綁定
C

提取 ProjectCard 元件 + 完整重設計

將卡片邏輯抽取成獨立的 ProjectCard.vue，在元件內重新設計 Wise 風格的 markup，ProjectListContent 改成呼叫此元件。最乾淨，但涉及元件拆分與 props 傳遞重構。

優點

  • 最乾淨的架構
  • 未來維護性最高

缺點

  • 改動面最大，需要定義 props interface
  • 超出「視覺重設計」的範疇

我的建議

選 B。它讓你得到完整的 Wise 視覺效果，同時把風險限制在 template 結構層面，不碰任何 props、emits、或業務邏輯。
