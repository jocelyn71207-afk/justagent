三種提升拆解精準度的方案

根據你的需求：多種 AI 消費場景 × 不同分類需要不同拆解策略

A

Category-Aware Chunking（分類驅動拆解）

每個分類套用不同的拆解策略，在 pipeline 的 chunking 階段就介入。

分類 拆解策略
商品文件每列一個 chunk（表格行拆解）
客服知識Q&A 配對拆解，問答不分離
規則說明條款段落拆解，保留標題上下文
系統文件章節拆解，保留層級結構

優點

  • chunk 品質最符合內容特性
  • 對所有 AI 消費方式都有效

代價

  • 需維護每個分類的策略設定
  • 新增分類時要同步更新策略
B

Metadata Prefix + Filter（語意注入 + 查詢過濾）

在每個 chunk 內容前面注入分類和標籤，讓向量帶有語意；查詢時加 filter 縮窄範圍。

// Chunk 內容（送入 embedding 前）
[分類:客服知識] [標籤:退款,流程]
原本的 chunk 文字內容...
// 查詢時的 filter
vector_search(query, filter: { category: '客服知識' })

優點

  • 改動小，不影響現有拆解邏輯
  • 搜尋時可精準鎖定分類

代價

  • chunk 本身的品質沒有提升
  • 需要向量 DB 支援 metadata filter
C

全管道整合（A + B 合體，推薦）

同時做 category-aware chunking 和 metadata prefix，搜尋端再加 filter。三層都覆蓋。

① 拆解品質
分類決定 chunk 策略，內容不被亂切
② 向量語意
category + tags 注入 chunk，向量更精準
③ 查詢過濾
搜尋時以 category 縮窄，提升 recall precision

優點

  • 三個維度都有提升，不依賴單一機制
  • 對 chatbot、搜尋、Agent 都通用
  • Tag 從此有實質功能，不只是標籤

代價

  • 實作工作量最大（但可分期）
  • 需要後端向量 DB 支援
