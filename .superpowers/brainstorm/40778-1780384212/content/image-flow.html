圖片拆解策略

三種圖片類型 → 兩條處理路徑 → 同一套 category-aware chunk 框架

決策流程

圖片上傳
png / jpg / gif / webp
↓
① OCR 嘗試
偵測圖片中是否有文字
文字夠多（>100字）↓
路徑 A：文字路徑
OCR 文字 → 套分類 chunk 策略
（chunk size / overlap 同文字檔）
適用：截圖、文件掃描圖
文字稀少 ↓
路徑 B：視覺描述路徑
Vision Model 生成描述
→ 描述文字作為 chunk
適用：商品圖、實物照片
↓（兩條路徑合流）
② Metadata Prefix 注入（同文字 chunk）
[分類:商品文件][標籤:...][來源:image] 描述或 OCR 文字...
↓
Embedding → Indexing
同文字流程，metadata 帶 source_type: 'image'

Vision Model Prompt 依分類客製化

分類 Vision Prompt 重點 描述範例
商品文件 外觀、顏色、材質、尺寸、特徵 「黑色無線耳機，頭戴式設計，右側有音量轉盤...」
系統文件 UI 元件、操作步驟、按鈕文字 「設定頁面截圖，左側選單有五個項目，紅色框標示...」
規則說明 條款文字、章節標題、重點標記 透過 OCR 取得（通常文字夠多，走路徑 A）
客服知識 圖示意義、流程說明、狀態圖 「退款流程圖，箭頭指向三個狀態：申請中、審核中、完成」

兩條路徑最終都產出 chunk 文字，後續流程與文字檔完全相同
