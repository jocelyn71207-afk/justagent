## 1. 產品概述

### 1.1 產品定位

Justagent 是一款面向零售電商企業的 AI Agent 協作平台，以「AI 虛擬員工」為核心概念，讓企業各部門（產料分析）能在統一的畫布介面中，透過對話方式驅動 AI Agent 執行工作流，包含競品分析、文件翻譯、銷售大幅降低重複性工作，提升整體效率。

### 1.2 核心價值

- 以畫布為中心的 AI 協作空間，融合文件、對話、分析結果於同一介面
- 跨部門共享資源庫，統一管理 AI 產出與人工上傳的檔案
- **知識內容管理系統**：結構化知識庫，支援版本審核、Pipeline 向量化、多來源匯入
- 企業級權限管理，支援多團隊、多角色的細粒度存取控制
- 垂直領域深度：專為零售電商場景設計，開箱即用的 Agent 工作流
- **探索中心**：發現與啟用各類 AI Agent 助理

### 1.3 目標

| # | 指標 | 目標 |
|---|---|---|
| 1 | 減少重複性工作 | 60–75% |
| 2 | 上線成本 | 約人力成本的 40% |
| 3 | 官網銷量提升 | 至少 20% |
| 4 | 降低新人入門時間 | 顯著改善 |

## 2. 目標用戶與使用情境

### 2.1 主要用戶群

| # | 角色 | 代表職位 | 主要痛點 |
|---|---|---|---|
| 1 | 產品運營人員 | 商品企劃、選品專員 | 選品流程耗時、競品分析工作量大 |
| 2 | 電商運營人員 | EC 主管、上架專員 | 上架流程繁瑣、圖文處理費時 |
| 3 | 行銷人員 | 行銷經理、BI 分析師 | 跨部門協作困難、資料整合費時 |
| 4 | 資料分析人員 | 數據工程師 | ERP 資料清理、報表生成費時 |
| 5 | 企業管理者 | IT 管理員、部門主管 | 權限管控、資料安全 |

### 2.2 核心使用情境

1. **競品分析**：上傳商品圖片 → AI 識別商品特徵 → 搜尋競品 → 深度分析 → 輸出 HTML 報告
2. **文件翻譯**：上傳 Excel/PPT/PDF → AI 翻譯 → 輸出對應格式檔案
3. **銷售報表**：匯入 ERP 當月銷售資料 → AI 整理計算 → 輸出分析報表
4. **畫布協作**：團隊成員在畫布上共同整理 AI 產出，結合評論與標注進行確認
5. **知識管理**（新增）：上傳/匯入企業知識 → Pipeline 向量化 → 審核發布 → AI Agent 查詢使用

## 4. 功能模組詳述

### 4.1 登入與初次設定

#### 4.1.1 帳號註冊
- User 自行完成帳號註冊
- 支援 Email / 密碼登入
- 支援社交帳號登入（OAuth）
- 登入入口：`/`（LoginView）；主應用入口：`/entrance`

#### 4.1.2 PM 大後台設置（前置作業）

User 完成註冊後，PM 取得帳號，在大後台完成以下設置，user 才能正常使用產品：

1. **設定企業類型**：目前僅支援「零售」
2. **設定團隊類型**：實體門市 / 電子商務
3. **設定版本方案**：Starter / Standard / Premium
4. **設定可使用的 Agent 類型**：依版本與企業需求開通對應 Agent

#### 4.1.3 初次使用 Onboarding

PM 設置完成後，user 登入，進行以下初次設定：

1. 輸入團隊名稱（上限 20 字）
2. 選擇團隊類型：實體門市 / 電子商務
3. 邀請協作帳號（選填，可略過）

完成後系統引導 user **建立第一個專案**，並開始使用 Agent。

### 4.2 專案管理

#### 4.2.1 專案列表頁

- 支援列表顯示與卡片顯示切換
  - 切換後，所有單元（最近專案、團隊專案等）同步切換顯示方式
- 專案卡片顯示：縮圖（AI 生成隨機底圖 + 壓上專案名稱）、標籤、最後編輯時間
- 工具列搜尋：即打即搜，僅搜尋專案名稱；切換單元後清除搜尋內容
- 最後編輯時間顯示規則：詳見第 5.3 節時間格式規則

#### 4.2.2 新增專案

- 填寫專案名稱（上限 20 字）
- 可選擇 AI 生成專案名稱（可無限次觸發，根據對話內容生成）
- 選擇對應 Agent
- 系統生成隨機背景圖，前端壓上專案名稱

#### 4.2.3 專案設定

- 修改專案名稱、描述、Agent
- 觸發最後編輯時間更新

#### 4.2.4 觸發「最後編輯時間」的行為

| # | 行為 | 更新 | 資料來源 |
|---|---|---|---|
| 1 | 修改「專案設定」 | ✅ | MySQL |
| 2 | 跟 Agent 對話 | ✅ | Mongo |
| 3 | 畫布：上傳/下載/註解/重命名 Block/複製/移除/拖曳 | ✅ | Mongo |
| 4 | 對話列表：刪除對話/開啟新對話 | ✅ | MySQL |
| 5 | 專案檔案清單：加到畫布/刪除 | ✅ | Mongo / MySQL |
| 6 | 畫布：帶入對話 | ❌ | 離開專案後不記錄 |

#### 4.2.5 專案垃圾桶

- 刪除邏輯（時間最小單位為「天」，00:01 與 23:59 刪除視為同一天）：
  - 刪除日為 n，正式刪除時間為 **n + 30 天 00:00:00**
  - 範例：3/1 刪除 → 3/2~3/30 可還原 → 3/31 00:00:00 正式刪除
- 介面上「剩餘天數」由前端計算（後端儲存的是正式刪除日期）
- 可執行：還原、確認永久刪除

#### 4.2.6 星號標記

- 標記黃色星星行為為**個人行為**（不影響其他成員視圖）
- ❌ 不支援：畫布內容查詢、評論查詢、專案檔案查詢加星號

### 4.3 畫布（Canvas）

#### 4.3.1 畫布概覽

畫布是平台的核心工作區，用戶可以：

- 放置並管理 Blocks（來自用戶上傳、Agent 生成、共享資源庫引入）
- 透過右側 AI Chat Panel 與 Agent 對話
- 進行多人即時協作

#### 4.3.2 Block 基本規則

- **Block 名稱預設**：使用 file_name，若名稱過長則直接截斷
- **Block 來源**：用戶上傳、Agent 生成、從共享資源庫引入
- **Block 類型**：PDF、Excel、PPT、圖片、Markdown、HTML、TXT、Word、Chart
- **搜尋（畫布搜尋）**：使用快捷鍵 `Ctrl + I`

#### 4.3.3 多人協作衝突處理

- 當用戶 1 正在移動某 Block 時，該 Block 被**鎖定**，其他用戶無法移動
- 鎖定狀態解除後，以**最後操作者的位置**為基準

#### 4.3.4 畫布操作說明

| # | 行為 | 說明 |
|---|---|---|
| 1 | 刪除（真刪除） | 從畫布上僅能「從畫布中移除」；真刪除需在專案檔案清單執行 |
| 2 | 重命名 | 修改 Block 的顯示名稱 |
| 3 | 複製 | 複製 Block 至畫布（Cmd+C / Cmd+V，碰撞偵測自動定位） |
| 4 | 縮放 Block | `Shift + 拖曳控制點`（等比放大縮小） |
| 5 | 新增評論 | 快捷鍵 `Ctrl + N` 開啟評論列表 |
| 6 | 多選模式 | `Shift + Command / Shift + Windows` |

#### 4.3.5 檔案刪除權限

| # | 文件類型 | 可刪除者 |
|---|---|---|
| 1 | 用戶上傳的檔案 | 該專案建立者 / 團隊主管以上 |
| 2 | Agent 生成的檔案 | 發起該對話的用戶 / 該專案建立者 / 團隊主管以上 |

備註：「專案建立者」為後端特殊標記（非角色權限），系統自動記錄建立該專案的 user。

#### 4.3.6 iframe 安全規範

- AI 產出的 HTML 中，所有 `<a>` 連結必須加上 `target="_blank"`
- ❌ 禁止上傳 `.html` 檔案（外部 JS 執行有安全疑慮）
- HTML 的 `focus` 在外部無法用按鍵控制，介面需於 Block 上顯示提示說明

### 4.4 AI Agent 對話

#### 4.4.1 競品分析 Agent — 對話介面規格

**整體架構**

對話介面分為兩個層次：

- **左側對話河道**：只顯示每步驟完成後的結果摘要
- **懸浮面板（Floating Panel）**：浮在輸入列正上方，承載所有互動操作

**懸浮面板規格**

- 位置：緊貼輸入列上方，`position: absolute; bottom: 56px`
- 開關：topbar 右側的「Step N・步驟名稱」膠囊 pill 可收合／展開
- 進度條：面板頂部顯示 1 → 2 → 3 → 4 → ✓ → 5 共六個節點，隨步驟同步更新

**步驟說明**

**Step 1 — 選擇商品分類**
- 單選 chip，點擊自動取消前一個選擇
- 底部提供自由輸入框，輸入時自動清除 chip 選取（兩者互斥）
- 確認後結果以 pill 形式推入對話河道

**Step 2 — 補充商品資訊**
- 必填欄位：品牌名稱、商品名稱、售價（TWD）、商品描述
- 選填：目標客群
- 四個必填欄位皆填寫後「確認」按鈕才啟用
- 確認後以 summary card 推入對話河道

**Step 3 — 選擇分析特徵**
- AI 依 Step 2 商品資訊自動產出五個核心特徵
- 多選，至少選 1 項，預設選取前兩項
- 右下方即時顯示「已選 N / 5」badge

**Step 4 — 設定搜尋範圍**
- 單選：台灣市場 / 全球 / 指定網域
- 確認後不直接搜尋，先進入 Step 4.5

**Step 4.5 — 確認設定內容（Review）**
- 整合顯示 Step 1–4 所有已填內容
- 每個 section 右側有「修改」按鈕，可跳回對應步驟（不清空已填內容）
- 確認無誤後點「確認無誤，開始搜尋」才觸發 DeepAgent

**Step 5 — 確認競品**
- DeepAgent 搜尋後產出 12 個候選競品
- 左右分欄佈局：左側為可捲動的競品列表，右側為圖片預覽窗格
- 游標懸停任一競品，右側即時顯示商品圖片、名稱、售價、相似度百分比
- 點擊勾選，最多選 5 個；選滿後其餘項目變灰無法點擊

**對話河道顯示格式**

| # | 步驟 | 顯示格式 |
|---|---|---|
| 1 | Step 1 | 單一 pill（商品分類） |
| 2 | Step 2 | Summary card（品牌、名稱、售價、描述） |
| 3 | Step 3 | Bubble + 特徵標籤群（info 色） |
| 4 | Step 4 | 單一 pill（搜尋範圍） |
| 5 | Step 4.5 | 單一 pill（✓ 設定已確認，success 色） |
| 6 | Step 5 | Bubble + 競品標籤群（info 色） |

#### 4.4.2 快速任務（Quick Task）

快速任務一：競品分析（三條入口路徑，最終輸出 HTML 分析報告）

- **路徑 A｜深度分析**（主路徑）：Step 1–5 完整流程 → 下載 `.html` 報告
- **路徑 B｜直接生成報告**（快速路徑）：跳過深度分析 → 直接輸出報告
- **路徑 C｜URL 輸入路徑**：輸入競品網址（最多 5 個）→ 爬取 → 特徵分析 → 生成報告

快速任務二：多格式文件翻譯

- 支援格式：PDF → `.pdf`、PPT/PPTX → `.pptx`、XLS/XLSX → `.xlsx`
- Excel 路徑：詢問 Sheet Name 與 Column Name，可指定翻譯範圍或整份翻譯
- ❌ 本階段不支援：CSV、Word

#### 4.4.3 任務進度（Task Progress）

任務進度獨立於對話河道，以獨立元件呈現。

**競品分析報告（Skill / Work-flow）**

| # | 進度步驟 | 觸發時機 |
|---|---|---|
| 1 | 識別圖片並結構化商品特徵 | 上傳圖片後 |
| 2 | 初步搜尋相似競品並彙整結果 | 生成初次報告中 |
| 3 | 深入分析競品價格、材質、特色 | 點擊「開始深度分析」後 |
| 4 | 整理重點並交付最終分析報告 | 生成最終報告中 ～ 完成 |

**文件翻譯（Work-flow）**

| # | 進度步驟 | 觸發時機 |
|---|---|---|
| 1 | 識別檔案類型並確認翻譯範圍 | 上傳檔案後 |
| 2 | 翻譯文件內容並輸出翻譯檔案 | 生成翻譯檔案中 ～ 完成 |

#### 4.4.4 分析報告生成規則

報告輸出格式為 `.html`，檔名規則如下：

- 有輸入產品名稱：`{產品名稱}_Competitor_AnalysisReport{YYYYMMDDHHmmss}.html`
- 無輸入產品名稱：`Competitor_AnalysisReport{YYYYMMDDHHmmss}.html`

#### 4.4.5 Agent 中止行為

- 僅支援「取消」，不做「暫停」
- 中止後，對話紀錄保留

### 4.5 共享資源庫

共享資源庫為跨專案、跨團隊的資源管理中心，包含兩個子模組：

1. **共用檔案管理**（ResourceLibrary）：一般檔案的上傳、管理、篩選
2. **知識內容管理**（KnowledgeBase）：結構化知識庫，詳見 4.6 節

#### 4.5.1 共用檔案管理功能說明

- 可查看誰上傳了哪個檔案
- 篩選：上傳者類型（使用者 / AI）、檔案類型
- 操作：重新命名、刪除、下載
- 卡片 / 清單視圖切換；支援分頁

#### 4.5.2 檔案操作行為矩陣

| # | 操作 | 畫布-用戶上傳 | 畫布-Agent生成 | 畫布-從共享資源庫引入 | 對話-用戶上傳 | 對話-Agent生成 | 專案清單-用戶上傳 |
|---|---|---|---|---|---|---|---|
| 1 | 上傳/新增 | ✅ | ✅（新增）| ❌ | ✅ | ✅（新增）| ❌ |

### 4.6 知識內容管理（新增）

知識內容管理為共享資源庫的子模組，提供結構化的企業知識庫，支援多來源匯入、AI Pipeline 向量化、版本管控與審核發布。

#### 4.6.1 知識條目生命週期

```
pending（待處理）
    ↓ Pipeline 觸發
processing（處理中）：chunking → embedding → indexing
    ↓ Pipeline 完成
reviewing（審核中）
    ↓ 審核通過
active（已發布）
    
active ──────────────────────→ needs_update（來源更新，需重新處理）
active ──────────────────────→ archived（封存）
processing / reviewing ──────→ failed（處理失敗）
```

**知識條目狀態說明**

| 狀態 | 中文 | 說明 |
|---|---|---|
| pending | 待處理 | 已建立但尚未觸發 Pipeline |
| processing | 處理中 | Pipeline 執行中（chunking → embedding → indexing）|
| reviewing | 審核中 | Pipeline 完成，等待人工審核 |
| active | 已發布 | 審核通過，可被 AI Agent 查詢 |
| needs_update | 需更新 | 來源檔案已更新，需重新觸發 Pipeline |
| failed | 失敗 | Pipeline 處理失敗 |
| archived | 封存 | 手動封存，不再對外提供 |

#### 4.6.2 知識內容管理頁（KnowledgeBase）

**頁面結構：兩個 Tab**

**Tab 1：知識條目**

統計卡（KPI 區）：

| 統計項 | 說明 |

| 全部 | 所有知識條目總數 |
| 已發布 | status = active 的條目數 |
| 需更新 | status = needs_update 的條目數 |
| 審核中 | status = reviewing 的條目數 |
| 知識轉換率（KPI）| 成功 active 條目 / 總條目，目標 ≥ 95% |

篩選工具：

- 狀態下拉篩選

- 批次刪除

**Tab 2：資料來源**

#### 4.6.6 分類（Category）設計規範

**設計原則**

分類決定 AI Pipeline 的拆解策略，不只是 UI 篩選用途：
- 每個分類對應不同的分段大小、重疊 token 與前綴標記
- 圖片的 Vision Model prompt 也依分類客製化
- **分類應按「使用情境 / 查詢意圖」設計，而非「文件格式」**
- 若兩個分類的拆解策略完全相同，合併成一個

**現有分類與 Chunking 參數**

| 分類 | Chunk Size | Overlap | 前綴標記 | 適用內容 |
|---|---|---|---|---|
| 商品文件 | 200 tokens | 20 | `[商品]` | 商品規格、庫存、選品資料 |
| 客服知識 | 300 tokens | 50 | `[客服]` | 客服 Q&A、處理流程、話術 |
| 規則說明 | 500 tokens | 100 | `[規則]` | 政策條款、作業規範、合規文件 |
| 系統文件 | 400 tokens | 80 | `[系統]` | 操作手冊、技術文件、介面說明 |

**建議補充分類（待業務評估）**

以下分類在拆解策略上與現有分類有明顯差異，建議視業務需求評估新增：

| 分類 | 建議 Chunk Size | 理由 |
|---|---|---|
| FAQ | 250 tokens / 50 overlap | 純 Q&A 格式，應以問答配對為最小單位，不應跨問題切割 |
| 操作手冊 | 350 tokens / 60 overlap | 步驟說明需保留前後步驟上下文，但比規則說明短 |
| 合約條款 | 600 tokens / 150 overlap | 法律條文語意密度高，比一般規則說明需要更多上下文 |
| 公告通知 | 150 tokens / 10 overlap | 短篇、時效性強，chunk 應小以提升搜尋精準度 |
| API 文件 | 300 tokens / 30 overlap | 結構化程度高，endpoint / 參數說明應作為獨立 chunk |

#### 4.6.7 標籤（Tag）設計規範

**現況問題**

標籤目前為完全 user 自由輸入（free-form），無預設選項。不同使用者對同一概念使用不同標籤（如「退款」「退款流程」「退貨退款」），導致向量搜尋的 tag filter 命中率低。

**設計方向：Hybrid 推薦 + 自由輸入**

產品端依分類定義推薦標籤，使用者可快速套用，也可自由新增：

```
[推薦] 退款  配送  換貨  規格  [+ 自訂標籤]
        ↑ 點選快速套用         ↑ 自由輸入
```

**各分類推薦標籤（初版）**

| 分類 | 推薦標籤 |
|---|---|
| 商品文件 | 規格、庫存、定價、選品、季節商品、配件 |
| 客服知識 | 退款、配送、換貨、會員、訂單、投訴 |
| 規則說明 | 退貨政策、隱私權、使用條款、保固、合規 |
| 系統文件 | 操作教學、設定、權限、串接、錯誤排除 |

**標籤治理原則**

- 推薦標籤由產品端維護，隨業務需求更新
- 鼓勵使用推薦標籤，但不強制
- 若某自訂標籤被大量使用，考慮升格為推薦標籤
- 標籤命名以**使用者會搜尋的詞語**為準，而非文件內部術語

#### 4.6.8 Pipeline 機制

**分段（Chunking）設定**

依知識分類採用不同的切分策略（參數詳見 4.6.6）。

**圖片處理**

- 若圖片 OCR 文字 ≥ 100 字元：走文字路徑（text path）
- 否則：走 Vision API 路徑，由 AI 生成描述文字
- 各分類有對應的 Vision 提示詞（商品/系統/規則/客服）

**Chunk 內容格式**

```
[分類:{category}][標籤:{tag1,tag2}][來源:{text|image}] {chunk_content}
```

**Pipeline 階段**

1. **chunking**：依分類策略切分內容為多個 chunk
2. **embedding**：對每個 chunk 生成向量
3. **indexing**：將向量寫入向量資料庫

Pipeline 完成後狀態自動轉為 `reviewing`，等待人工確認。

#### 4.6.9 審核流程（ReviewDrawer）

- 審核人可在 ReviewDrawer 中查看 Pipeline 生成的摘要與 Chunk 列表
- 操作：批准發布（status → active）/ 退回（status → rejected，需填退回原因）
- 批准後最新草稿版本成為 active 版本，舊版本轉為 history

### 5.5 星號標記

- 星號標記為**個人行為**，不影響其他用戶的視圖
- ❌ 不支援：畫布內容查詢、評論查詢、專案檔案查詢加星號

### 5.6 主題切換（Dark / Light Mode）

#### 5.6.1 功能說明

- 所有 `/view/*` 頁面皆支援 Light / Dark 雙主題
- 切換元件（`AppThemeToggle`）固定顯示於主框架頂部，切換後**即時**套用至全站

#### 5.6.2 切換機制

| 項目 | 說明 |
|---|---|
| 切換方式 | 點擊 Light / Dark toggle（日月圖示切換）|
| 預設主題 | Light Mode |
| 系統偏好 | 支援 `prefers-color-scheme`，自動跟隨作業系統設定 |
| 實作方式 | 切換時在 `<html>` 加上 `data-theme="dark"` / `"light"` attribute |
| 覆寫優先序 | 手動切換 > 系統偏好（`prefers-color-scheme`）|

#### 5.6.3 色彩規範

## 7. 非功能需求

### 7.1 安全性

- 符合 ISO 27001:2022 認證
- iframe 內容需過濾外部 JS 引用
- HTML 上傳禁止
- 所有 AI 產出 HTML 中的超連結強制加上 `target="_blank"`
- 用戶登出後所有 Session Token 失效

### 7.2 效能

- Agent 執行採 WebSocket 長連線（因 API 30 秒限制，agent 思考時間需 WebSocket 支持）
- 大型 AI 任務（如競品分析）不阻塞用戶其他操作
- 畫布多人協作採文件鎖定機制（optimistic locking）
- 知識 Pipeline（chunking / embedding / indexing）非同步執行，不阻塞前端操作

### 7.3 可靠性

- 檔案上傳：支援背景上傳，失敗時提示重試
- Agent 中止後，對話紀錄完整保存
- 軟刪除機制確保資料可還原
- Knowledge Pipeline 支援重新觸發，失敗紀錄完整保存（ConversionLog）

### 7.4 相容性

- 支援 Web（桌面瀏覽器）
- 支援觸控板操作（雙指縮放）
- 現有配色需注意螢幕色彩差異，增加顏色對比度
