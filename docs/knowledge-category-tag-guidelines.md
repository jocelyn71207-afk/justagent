# 知識庫：分類與標籤設計規範

---

## 一、分類（Category）

### 設計原則

- 分類決定 AI pipeline 的拆解策略，不只是 UI 篩選用途
- 每個分類對應不同的 chunk 大小、overlap、語意前綴
- 圖片的 Vision Model prompt 也依分類客製化
- 分類應按「使用情境 / 查詢意圖」設計，而非「文件格式」
- 若兩個分類的拆解策略完全相同，合併成一個即可

---

### 現有分類與拆解參數

**商品文件**
- Chunk Size：200 tokens
- Overlap：20 tokens
- 語意前綴：[商品]
- 適用內容：商品規格、庫存、選品資料

**客服知識**
- Chunk Size：300 tokens
- Overlap：50 tokens
- 語意前綴：[客服]
- 適用內容：客服 Q&A、處理流程、話術

**規則說明**
- Chunk Size：500 tokens
- Overlap：100 tokens
- 語意前綴：[規則]
- 適用內容：政策條款、作業規範、合規文件

**系統文件**
- Chunk Size：400 tokens
- Overlap：80 tokens
- 語意前綴：[系統]
- 適用內容：操作手冊、技術文件、介面說明

---

### 建議補充分類

以下分類在拆解策略上與現有分類有明顯差異，建議視業務需求評估新增：

**FAQ（常見問題）**
- 建議 Chunk Size：250 tokens / Overlap：50
- 原因：純 Q&A 格式，應以問答配對為最小單位，不應跨問題切割

**操作手冊**
- 建議 Chunk Size：350 tokens / Overlap：60
- 原因：步驟說明需保留前後步驟上下文，但比規則說明短

**合約條款**
- 建議 Chunk Size：600 tokens / Overlap：150
- 原因：法律條文語意密度高，比一般規則說明需要更多上下文

**公告通知**
- 建議 Chunk Size：150 tokens / Overlap：10
- 原因：短篇、時效性強，chunk 小一點更適合精準搜尋

**API 文件**
- 建議 Chunk Size：300 tokens / Overlap：30
- 原因：結構化程度高，endpoint / 參數說明應作為獨立 chunk

---

### 新增分類的檢查清單

新增分類前，確認以下項目：
- 與現有分類的拆解策略有實質差異
- 有對應的 Vision Model prompt（處理圖片時使用）
- 在 getChunkingConfig() 新增對應設定
- 在 getVisionPrompt() 新增對應 prompt
- 在知識條目編輯頁的分類下拉選單新增選項

## 二、標籤（Tag）

### 現況問題

- 目前標籤為完全 user 自由輸入，無預設選項
- 不同使用者對同一概念使用不同標籤（例如：「退款」「退款流程」「退貨退款」）
- 導致 tag 搜尋過濾的命中率低，標籤失去實質功能

---

### 建議：Hybrid 設計

產品端定義推薦標籤（per 分類）＋ 使用者可自由新增

做法：
- 每個分類在 UI 上顯示一組推薦標籤 chip，使用者點選即套用
- 使用者仍可自由輸入自訂標籤
- 推薦標籤儲存在前端 config，不需後端支援

---

### 各分類推薦標籤（初版）

**商品文件**
- 規格、庫存、定價、選品、季節商品、配件

**客服知識**
- 退款、配送、換貨、會員、訂單、投訴

**規則說明**
- 退貨政策、隱私權、使用條款、保固、合規

**系統文件**
- 操作教學、設定、權限、串接、錯誤排除

---

### 標籤治理原則

- 推薦標籤由產品端維護，隨業務需求更新
- 鼓勵使用推薦標籤，但不強制
- 若某個自訂標籤被大量使用，考慮升格為推薦標籤
- 標籤命名以使用者會搜尋的詞語為準，而非文件內部術語
